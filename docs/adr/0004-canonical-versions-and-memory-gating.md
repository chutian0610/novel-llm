# Gate canonical state and memory behind review

A Chapter points to one Markdown Canonical Chapter Version using a constrained block-and-paragraph subset, while model-generated, model-revised, and author-edited variants remain Candidates with their evaluations, diagnoses, and review history attached. Manual edits therefore pass through the same review gate as generated content and record their base version; conflicting base versions require an explicit rebase, overwrite, or fork decision. A Project Outline is published as one immutable version containing work, volume, chapter, scene, foreshadowing, and constraint plans. A Story Bible has a Bible Draft plus immutable Published Bible Versions; generation references a published version, and extraction or interview output becomes fine-grained Bible Change Proposals rather than overwriting authoritative facts. Bible identity is split from Bible content: stable identities and aliases persist across versions while each version freezes its entries and relationships. Stable identity merges and splits change only through human review. Story events distinguish Narrative Time from Disclosure Order, allowing nonlinear narration. State Increment Memory is derived only from Canonical Chapter Versions, so rejected candidates cannot contaminate long-term narrative state; projections are ordered immutable increments with deterministic derived state. Rewriting an earlier canonical chapter marks downstream derived memory stale without automatically invalidating later chapters. Existing-fiction extraction additionally requires an authorization declaration and preserves provenance and short citations rather than treating source prose as reusable style-cloning material.

Jobs bind their Bible version, upstream canonical chapter versions, memory projection, outline, user instructions, model profile version, prompt template versions, and context profile when created. Context Packages retain their selected sources, ranking, scores, reasons, and significant exclusions. Exports likewise bind an immutable list of canonical chapter versions. Approval of a chapter enqueues memory projection, but does not automatically generate the next chapter by default; an explicit configuration may enable that behavior. Automated judges produce advisory structured evaluations, diagnoses, rankings, and stop reports only; human review remains the authority for canonical state. The first quality loop defaults to two candidates, one diagnosis-and-revision round, and one recheck. Evaluation rubrics cover canon consistency, continuity, outline fulfillment, character motivation, pacing, prose quality, constraint compliance, and repetition, with evidence and severity attached. Quality loops have maximum iteration, cost, and duration limits and retain the best candidate plus a final report when limits are reached.
