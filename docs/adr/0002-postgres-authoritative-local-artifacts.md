# Keep authoritative state in PostgreSQL and payloads on local storage

PostgreSQL is the sole source of truth for projects, chapters, Bible versions, workflow state, review decisions, domain events, model traces, and model configuration. Infrastructure configuration comes from `config/default.toml`, local overrides come from gitignored `config/local.toml`, and tests use `config/test.toml`; production model configuration is read from database tables. Provider credentials are stored separately from model profiles: a profile names the provider and model behavior while a credential authorizes access to the provider. Uploads, exports, snapshots, and other large payloads live on the local filesystem through content-addressed storage, with their path, media type, size, checksum, and lifecycle state recorded in the database. The first version does not garbage-delete uploads, exports, snapshots, or traces; it only marks lifecycle state. Full-text search indexes canonical chapter text, Bible entries, chapter summaries, event descriptions, and retrieval documents; candidates remain isolated to their workflow and review context. SSE is an optimization over durable append-only events using a versioned envelope and cursor: clients can reconnect and recover anything missed. Langfuse is not a default dependency; database model traces and structured correlation logs provide the first debugging surface. Automated backup and restore verification are deliberately out of scope for the first implementation.

Business tables use snake-case plural names and UUIDv7 primary keys. Volume and chapter structure use stable IDs plus mutable positions rather than sequence-derived identity. Domain references use strongly typed UUID columns and indexes rather than physical foreign keys; referential integrity is checked by domain services inside transactions. Domain objects are archived or superseded instead of hard-deleted.
