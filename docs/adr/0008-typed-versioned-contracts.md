# Use typed, versioned execution and API contracts

The public API is versioned under `/api/v1`, generated into a typed frontend client, and returns problem-details errors with stable error codes. List endpoints use cursor pagination, state-changing creations accept idempotency keys, and mutable objects use versioned optimistic concurrency through ETag or `If-Match`. Model execution has explicit contracts: writing models return Markdown plus metadata, while evaluation, diagnosis, extraction, and projection models return typed JSON validated by Pydantic. A structurally invalid model response gets at most one repair call, and both the original and repair traces are retained. Prompt templates are semantically versioned in code, fully rendered into traces, and bound to the Job together with its model and context profiles. The interface defaults to Simplified Chinese and stores the configured project language for generated domain content.

`/healthz` reports process liveness, `/readyz` checks the expected database migration and queue availability, and the Worker reports through database heartbeats rather than an HTTP listener. API and gateway layers validate maximum chapter, upload, model-output, and context-package sizes. Unit tests cover state machines and invariants, PostgreSQL integration tests cover queueing, checkpointing, events, and zhparser search, and the deterministic fake provider drives the end-to-end framework acceptance scenario without external model access. `make check` runs Python formatting/static checks and tests, frontend checks and tests, and OpenAPI client drift checks; it is the merge gate.
